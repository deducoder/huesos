# Problem brief: {slug}

**Date:** {YYYY-MM-DD}

## 1 · Domain

{what kind of problem — delivery / quality / visibility / other}

## 2 · For whom

{the primary stakeholder who feels it directly}

## 3 · Current state

{who} can't {do what} because {reason} — observable, not a solution.

## 4 · Root cause (3 whys)

{the root cause, confirmed with the stakeholder}

**Distinct from** a bug analysis's `Root cause`, which is the technical cause
of a defect. This one is the cause of a **problem worth solving** — why the
current state persists — and it is confirmed with the stakeholder, not with a
stack trace.

## 5 · Early signal (4 weeks)

{what would change first, a leading indicator}

## 6 · Hypothesis

If {current state}, then {early signal} for {stakeholder}, measured by {metric}.

**Distinct from** the epic brief's `Hypothesis`, which is a *positioning*
statement (`For {users} who {pain}, the {solution} is a {category}…`). This one
is *causal and measurable*: it states what should change and how you would
know. `epic-start` reads this one to fill the brief's **Success metrics**, not
the brief's hypothesis.
